# 0003 Stage 2 值模型与 NIR schema 3

## 背景

Stage 1 已完成前端事实结构化、模块解析器扩展点、NIR schema 2 调试段和源码位置映射。Stage 2 要加入字符串、对象、数组、联合、函数值和泛型，必须先确定值模型、Runtime ABI 边界和 NIR 类型表示，否则每个特性会各自决定一套布局。

字符串有一个特殊约束：JavaScript/TypeScript 开发者观察到的长度、索引和切片通常以 UTF-16 code unit 为单位，而 Go 字符串以 UTF-8 字节为底层表示。直接使用 Go `len(string)` 会改变用户可见语义。

## 选项

1. **继续使用 NIR 字符串类型**：每个字段写 `"string"`、`"number[]"` 之类文本。实现快，但结构化类型无法稳定比较，且每加一种类型都要改字段含义。
2. **NIR 内联结构化类型**：在每个字段里重复类型结构。表达力够，但重复、难去重、回放和调试信息会膨胀。
3. **模块级类型表**：类型定义一次，执行字段引用类型 ID；内置类型使用保留 ID。需要一次 schema 升级和迁移，但后续值类型可以持续扩展。

## 决定

选择 3，同时确定以下值模型：

- **字符串**：UTF-16 存储，ABI 为 `{data *uint16, len int32}`；`length`、索引、`slice`、相等按 UTF-16 code unit，遍历按 Unicode 码点。索引越界返回 `undefined`；空值表示已随 S2.4 可空联合落地，字符串索引访问本身仍待实现。模板插值首版只接受 `string` / `number` / `boolean`。
- **对象**：静态形状布局、引用身份、编译期结构兼容；可选属性用存在性标记，读取缺失属性返回 `undefined`；字段写入进入第二个对象切片；不支持动态键和索引签名。
- **数组**：同质 `T[]`，首版越界采用运行时边界错误（进程退出 6），这是有意不同于 JavaScript `undefined` 的行为；元组固定长度，索引越界在编译期拒绝；数组切片复制，不共享底层存储。
- **联合与空值**：`null` 和 `undefined` 都是独立类型和值；联合使用 `tag int32` 加按最大成员对齐的 payload；`??` / `?.` 使用 JavaScript 短路语义。
- **函数与闭包**：函数值使用 `code uintptr + env *ClosureEnv` ABI；闭包按引用捕获，允许捕获可变 `let`，生命周期由 GC 管理；Go `func` 不进入公共 API。
- **泛型**：单态化；NIR 不保留运行时类型参数；首版约束只支持有限集合，类型实例缓存键使用结构化类型身份。
- **NIR schema 3**：内置类型 ID 1–7 为 `number`、`bool`、`void`、`string`、`null`、`undefined`、`never`；复合类型 ID 从 8 开始；`Function.result`、`Param.type`、`Stmt.type`、`DebugLocal.type` 改为类型 ID；允许通过 ID 表达递归对象类型，验证器和消费者使用遍历预算；类型去重忽略 `name`。

NIR schema 3 的详细字段、迁移和校验见[设计记录](../design/nir-schema-3-types.md)。

## 影响

- Stage 2 的第一批实现是类型表、v2→v3 迁移、降低器类型 ID 改写和调试段类型 ID。
- 字符串最小闭环只做字面量、拼接、`length`、严格相等和 `console.log`，先验证新类型穿过 Facts → NIR → Runtime → 原生输出的整条链路。
- 对象、数组、联合和函数按 Stage 2 工作包逐个加入，类型表从第一天就能描述它们。
- Go bridge 需要接受 schema 1/2/3；v1/v2 在写快照前迁移到 v3。
- 数组越界和字符串索引越界暂时采用不同行为，必须在文档中显式记录；S2.4 已提供空值表示，统一语义仍待复评。

## 代价与风险

- UTF-16 存储让 ASCII 字符串占用约为 UTF-8 的两倍，换来实现简单和 code unit 语义直接。
- 类型表引入一次破坏性 schema 升级，旧二进制会拒绝 v3。
- 静态对象形状和同质数组限制首版表达力，但避免动态字典和稀疏数组的复杂度。
- 数组越界与字符串索引越界暂时不一致，可能让用户困惑；通过诊断和文档明确说明。
- 闭包按引用捕获会暴露逃逸和生命周期问题，需要 Runtime ABI 和 GC 测试。

## 复评条件

- UTF-16 内存成本成为实际瓶颈；
- 数组越界和字符串索引越界需要统一语义；
- 对象动态键、索引签名或对象展开进入实际需求；
- 单态化导致不可接受的代码体积或编译时间；
- 闭包捕获或函数值 ABI 无法在 Go Runtime 上稳定实现；
- NIR schema 3 的类型表出现难以迁移的结构性缺陷。
