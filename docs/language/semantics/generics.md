# RFC：泛型基础

> 状态：S2.0 已确认；第一个切片（泛型函数单态化）已实现，泛型接口与约束驱动操作待后续
> 关联：[Stage 2 计划](../../plans/stage-2.md)、[NIR schema 3](../../design/nir-schema-3-types.md)、[语义索引](README.md)

## 1. 目标

支持常见泛型函数、泛型接口和类型参数约束，为可复用标准库和类型安全 API 打基础。

## 2. 推荐策略

推荐**单态化**：

- 调用点提供类型实参，编译器为每组实际类型生成一份具体函数；
- 泛型函数在 NIR 里不保留运行时的类型参数；
- 函数名按类型实参加后缀，避免符号冲突；
- 约束在编译期检查，不进入运行时；
- 首版不支持运行时反射式类型参数。

单态化的优点是运行时简单、布局固定、容易复用现有 NIR；代价是代码体积和编译时间。字典传递和类型擦除留到有明确需求时再评估。

第一个切片从实参类型推断类型实参，为每组具体类型生成一个实例，名字形如 `identity$t1`、`identity$t4`；类型 ID 在同一个模块内稳定，重复调用复用同一个实例。NIR 的 `types` 表和函数签名里不会出现 `type-parameter`。

## 3. 类型参数与约束

- 支持 `function identity<T>(value: T): T`；
- 支持泛型接口/对象类型，例如 `Box<T>`；
- 首版约束只支持基础形状：`T extends string | number`、`T extends object` 这类有限集合；
- 默认类型参数先记录，不要求首个切片实现；
- 类型参数推断只做调用点直接推断，不做复杂条件推断。

第一个切片只实现泛型函数。类型参数可以出现在顶层参数、数组元素、元组位置、对象属性和函数类型里；联合与泛型别名不参与推断。约束由 TypeScript 在调用点检查，本轮不把约束写入事实；函数体仍然只能使用当前子集支持的运算，例如 `T extends number` 不会让 `value + 1` 自动通过能力检查。

## 4. NIR schema 3 影响

- 类型表可以包含类型参数占位，但单态化后的 NIR 不保存未实例化类型参数；
- 泛型函数在降低时实例化成具体函数，类型表用实际类型 ID；
- 调试段记录实例化后的函数名和类型 ID；
- 函数名后缀需要稳定、可回放，不能依赖 Go 的符号命名规则。

## 5. 暂缓

- 条件类型、映射类型、`infer`；
- 变型（协变/逆变）和高级类型运算；
- 运行时泛型和反射；
- 泛型类、泛型方法；
- 高阶类型参数。

## 6. 验收用例

第一个切片已覆盖：

- `identity<number>`、`identity<string>` 生成两个具体函数；
- 同一类型实参重复调用复用同一实例；
- 泛型函数与字符串、数组、对象和函数类型组合；
- 递归泛型调用；
- NIR 回放和原生输出。

后续切片：

- 泛型对象 `Box<T>` 的属性类型；
- 显式类型实参、默认类型参数和约束驱动的操作；
- 泛型接口与泛型类型别名；
- 约束不满足时的专门诊断（TypeScript 已经会拒绝）。

## 7. 已确认决定

1. **实现策略**：单态化；NIR 不保留运行时类型参数，函数名按实例类型稳定生成。
2. **首个切片**：先支持泛型函数和调用点推断单态化，再支持泛型接口/对象、显式类型实参与默认类型参数。
3. **约束子集**：首版只支持 `T extends string | number`、`T extends object` 这类有限集合。
4. **去重**：实例缓存键使用结构化类型身份；类型名不参与缓存键。

## 8. 复评条件

- 单态化导致代码体积或编译时间不可接受；
- 泛型接口需要运行时类型信息；
- 约束表达能力成为标准库瓶颈；
- 条件类型或映射类型进入语言范围。
