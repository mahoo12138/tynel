# RFC：联合、`null` / `undefined` 与缩窄

> 状态：S2.0 已确认，待实现  
> 关联：[Stage 2 计划](../../plans/stage-2.md)、[NIR schema 3](../../design/nir-schema-3-types.md)、[语义索引](README.md)

## 1. 目标

定义联合类型、空值和类型缩窄的可观察规则，为字符串、对象和数组的可选性提供统一基础。

## 2. 推荐语义

- `null` 和 `undefined` 是独立类型和独立值；
- 联合类型 `A | B` 保留成员集合；
- 判别联合用字面量类型字段作为标签；
- 控制流缩窄至少支持：
  - `x === null` / `x !== null`；
  - `x === undefined` / `x !== undefined`；
  - `typeof x === "string"` 等基础判断；
  - 判别字段的 `===` 比较；
  - `in` 操作符在对象联合上的判断；
- `??` 和 `?.` 按 JavaScript 的短路语义执行：右侧或属性链只在需要时求值；
- 未选中的缩窄分支不执行，但仍然做类型检查和能力检查。

## 3. 表示

推荐带标签的联合：

```text
TynelUnion(A | B) {
    tag  int32
    data 按成员最大布局对齐
}
```

- 标量联合可以优化成标签 + 标量槽位，不强制装箱；
- 对象和字符串联合使用指针槽位；
- 可选属性可以用存在性标记表达「缺失」，与显式 `undefined` 区分；
- 联合的 ABI 由类型表决定，不允许后端自行选择不一致布局。

首版可以先支持 `T | undefined` 和 `T | null` 两种简单联合，再扩展到多成员判别联合。

## 4. NIR schema 3 影响

- 类型表增加 `union`，成员引用类型 ID；
- 增加 `null` / `undefined` 常量操作；
- 增加标签读取、标签比较和按标签取值的操作；
- 缩窄在降低阶段转成显式分支，不把 TypeScript 的流分析留到运行时；
- 调试段的类型引用联合类型 ID。

## 5. 暂缓

- 复杂条件类型、映射类型和 `infer`；
- 精确可选属性语义（`exactOptionalPropertyTypes`）；
- 交叉类型和完整类型运算；
- `any` / `unknown` 的受控动态表示；
- 多成员联合的装箱优化。

## 6. 验收用例

- `number | null`、`string | undefined` 的赋值和缩窄；
- 判别联合的两个分支；
- `??` / `?.` 的短路与副作用顺序；
- 未选中分支不执行；
- 缺失属性与显式 `undefined` 的区分；
- 类型错误：未缩窄就访问成员、标签不匹配；
- NIR 回放和原生输出。

## 7. 已确认决定

1. **空值**：`null` 和 `undefined` 都是独立类型和值；S2.4 同时实现。
2. **联合表示**：使用 `tag int32` 加按最大成员对齐的 payload；简单 `T | undefined` / `T | null` 先落地，再多成员判别联合。
3. **可选属性**：存在性标记与 `undefined` 表示共用，读取缺失可选属性返回 `undefined`。
4. **索引越界**：字符串和后续数组的 JS 兼容路径返回 `undefined`；首版数组仍按对象数组 RFC 的运行时边界错误处理，S2.4 后复评。
5. **短路**：`??` / `?.` 采用 JavaScript 短路语义，未选中路径不执行但仍接受检查。

## 8. 复评条件

- 数组越界行为与字符串索引语义需要统一；
- 多成员联合的装箱成本过高；
- 精确可选属性或 `any` / `unknown` 进入实际需求。
