# RFC：对象、数组与元组

> 状态：S2.0 已确认；对象第一个切片和数组/元组第一个切片（字面量、索引、`length`、编译期元组索引）已实现，数组方法与身份比较待后续
>
> 关联：[Stage 2 计划](../../plans/stage-2.md)、[NIR schema 3](../../design/nir-schema-3-types.md)、[语义索引](README.md)

## 1. 目标

定义典型 TypeScript 数据建模所需的对象、数组和元组语义，并给出第一版布局方案。首版优先静态形状和同质数组，不追求动态键和完整 JavaScript 数组行为。

## 2. 对象

### 2.1 推荐语义

- 对象字面量创建具有静态形状的对象；
- 属性访问按名字解析到固定偏移；
- `===` / `!==` 使用引用身份，不做结构相等；
- 对象类型兼容在编译期按结构判断：目标形状的每个属性在来源对象上存在且类型兼容；
- 可选属性用存在性标记区分「缺失」与显式 `undefined`；
- 首版不支持动态键、索引签名、`delete`、原型链和对象展开；
- 对象字段写入作为第二切片，先支持字面量和属性读取。

### 2.2 表示与 ABI

推荐静态形状布局：

```text
TynelObject(Point) {
    x     float64
    label Maybe<string>
}
```

- 每个不同形状分配稳定布局 ID；
- 可选属性使用存在性标记或空值槽位，由 S2.4 的空值表示决定；
- 字段中的指针必须对 GC 可见；
- 对象引用是 GC 可见指针，身份由分配地址决定；
- 不把 Go struct 的内存布局直接暴露为 Tynel ABI。

### 2.3 NIR schema 3 影响

- 类型表增加 `object` 类型，带属性名、可选性和类型 ID；
- 新增 `object` 字面量操作和 `field` 读取操作；
- 对象字面量的求值顺序按源码顺序；
- 对象身份和引用比较由 Runtime 负责。

## 3. 数组

### 3.1 推荐语义

- 首版只支持同质数组 `T[]`；
- 数组字面量按源码顺序求值；
- `length` 返回当前元素个数；
- 索引访问做运行时边界检查；越界作为 Tynel 运行时错误，不沿用 Go 的 panic；
- 不支持稀疏数组、异质数组、动态属性；
- `push` / `slice` 等方法放到标准库阶段，核心语言先有字面量、索引和 `length`。

越界行为是有意与 JavaScript 不同的地方：JavaScript 返回 `undefined`，Tynel 首版选择显式运行时错误，避免每个索引结果都变成 `T | undefined`。该决定需要在实现前确认。

首个实现切片已经落地：同质数组字面量、索引和 `length` 可用，索引越界按运行时数据错误退出 6；数组作为参数、返回值、局部值、对象字段和三元式结果也可以生成原生代码。`push` / `slice`、展开、赋值、扩容和 `===` 身份比较仍未实现。bridge 目前用 Go 切片承载数组，切片头对 GC 可见；长期 ABI 仍以 `TynelSlice(T)` 为目标，不能把 Go 切片头当作公开布局。

### 3.2 表示与 ABI

```text
TynelSlice(T) {
    data *T
    len  int32
    cap  int32
}
```

- 元素类型由类型表给出；
- 元素中的指针必须对 GC 可见；
- 扩容、共享和写屏障由 Runtime 统一处理；
- 切片复制还是共享在 RFC 复评时决定。

## 4. 元组

- 元组是固定长度、固定位置类型的数组特例；
- 索引越界在编译期拒绝；
- 布局按元素顺序固定；
- 首版元组只支持读取和字面量，不支持可变长度操作。

首个切片已经支持元组字面量、常量整数索引、元组参数和返回值。变量索引和空元组明确拒绝；元组值在 bridge 里是 `*struct{f0 T0; ...}`，位置固定，`===` 身份比较尚未实现。

## 5. NIR schema 3 影响

类型表增加：

- `object`：属性列表；
- `array`：元素类型 ID；
- `tuple`：元素类型 ID 列表。

操作增加：

- `object` 字面量；
- `field` 读取；
- `array` / `tuple` 字面量；
- `index` 读取；
- `len` 读取数组长度（字符串已有 `strlen`）。

所有类型字段引用类型表 ID，不内联类型字符串。

## 6. 暂缓

- 动态键、索引签名、`delete`、原型链；
- 对象展开、解构、计算属性；
- 稀疏数组、异质数组、数组方法；
- 对象字段写入和数组扩容的首版支持；
- 结构相等的运行时实现。

## 7. 验收用例

- 空对象、单字段、多字段、嵌套对象；
- 可选属性缺失、显式 `undefined`；
- 对象引用相等与内容相同的两个对象；
- 结构兼容赋值和缺字段诊断；
- 空数组、单元素、多元素、中文/emoji 元素；
- 索引访问、越界、`length`、嵌套数组；
- 元组固定长度和越界编译期拒绝；
- NIR 回放和原生输出。

## 8. 已确认决定

1. **数组越界**：首版采用运行时边界错误（进程退出 6），这是有意不同于 JavaScript `undefined` 的行为；等 S2.4 的空值和联合表示稳定后再复评是否改为 `undefined`。
2. **对象字段写入**：进入第二个对象切片；第一个切片只做对象字面量、属性读取和对象身份。
3. **可选属性**：用存在性标记区分「缺失」；读取缺失可选属性返回 `undefined`，该读取在 S2.4 落地后启用。首个对象切片先支持必填属性。
4. **数组切片**：`slice` 采用复制语义，不共享底层数组；扩容和数组方法放到标准库阶段。
5. **结构兼容**：编译期按结构判断，运行时布局由形状决定；对象 `===` 使用引用身份。

## 9. 复评条件

- 数组越界行为影响真实程序的可移植性或标准库设计；
- 可选属性读取必须先于 S2.4 启用；
- 动态键、索引签名或对象展开进入实际需求；
- 数组扩容和切片共享成为性能瓶颈。
