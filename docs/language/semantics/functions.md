# RFC：函数值与闭包

> 状态：S2.0 已确认；第一个切片（无捕获函数值与箭头）已实现，闭包待后续
> 关联：[Stage 2 计划](../../plans/stage-2.md)、[NIR schema 3](../../design/nir-schema-3-types.md)、[语义索引](README.md)

## 1. 目标

让函数可以作为值传递、返回和调用，并为回调、集合操作和闭包提供明确的调用约定。

## 2. 推荐语义

- 支持箭头函数、函数表达式和函数类型；
- 函数值按引用身份比较；
- 回调调用保持实参从左到右求值；
- 闭包捕获外层局部值时按引用捕获，生命周期由 GC 管理；
- 首版不支持 `this`、方法、生成器和重载；
- 跨模块传递函数值需要稳定的调用 ABI，不能暴露 Go `func` 类型。

## 3. 表示与 ABI

推荐函数值表示为：

```text
TynelFunc {
    code uintptr
    env  *ClosureEnv
}
```

- `code` 指向原生函数入口；
- `env` 指向 GC 可见的捕获环境；无捕获时为 nil；
- 调用约定、参数布局和返回值布局由 Tynel Runtime ABI 定义；
- Go 的 `func` 值只作为后端实现细节，不进入 NIR 或公共 API；
- 闭包环境中的指针字段必须对 GC 可见。

第一个切片没有捕获环境，bridge 暂时直接用 Go func 值表示函数值；这在语义上等价于「代码入口加空环境」。闭包落地时再引入显式的 `code + env` 布局。

## 4. NIR schema 3 影响

- 类型表增加 `function`，带参数类型 ID 列表和返回类型 ID；
- 增加函数值构造操作、间接调用操作和闭包创建操作；
- 函数值调用的实参顺序和副作用必须与直接调用一致；
- 调试段记录函数值局部变量的类型 ID。

## 5. 暂缓

- `this`、类方法、访问器和绑定；
- 生成器、`yield` 和异步函数；
- 函数重载的实现选择；
- 尾调用优化和跨模块内联。

## 6. 验收用例

第一个切片已覆盖：

- 把顶层函数赋给函数类型变量并调用；
- 箭头函数作为参数和返回值；
- 回调调用顺序和副作用；
- 函数类型三元式结果；
- NIR 回放和原生输出。

后续切片：

- 闭包捕获可变局部值，外层返回后仍可读取；
- 多个闭包共享同一捕获环境；
- 函数值引用相等和不同函数值不等；
- 类型错误：参数或返回值不匹配（TypeScript 已能拒绝）。

## 7. 已确认决定

1. **函数值表示**：使用 `code uintptr + env *ClosureEnv`，Go `func` 只作为后端实现细节。
2. **闭包捕获**：按引用捕获，允许捕获可变 `let`；生命周期由 GC 管理。
3. **首个切片**：先支持无捕获的顶层函数值和表达式体箭头函数，再支持闭包；块体箭头与 `void` 箭头暂缓。
4. **调用约定**：参数、返回值布局由 Tynel Runtime ABI 定义，跨模块函数值使用同一 ABI。

## 8. 复评条件

- 闭包捕获可变局部值导致逃逸或性能问题；
- 跨模块函数值需要额外的 ABI 版本字段；
- `this`、方法或异步函数进入语言范围。
