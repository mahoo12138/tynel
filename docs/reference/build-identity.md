# 构建身份与依赖变化

05.07 给每次构建写一份内容身份。它回答两个问题：这次到底用了哪些源码、配置和工具；其中一项变化后，新结果还能不能称为同一次构建。

构建身份只由内容决定，不看开始时间、耗时、输出路径或当前工作目录。同一组输入换个输出位置或换个工作目录，身份不变。

## 两个哈希

一次构建记录两个哈希，职责不同：

| 字段 | 覆盖范围 | 用途 |
| --- | --- | --- |
| `identity.hash` | 入口、全部类型和值依赖的路径与 sha256、NIR 字节、配置、工具链内容 | 复核这次构建的完整输入；任何源码或工具变化都会改变它 |
| `identity.artifactSha256` | NIR 字节、配置、工具链内容 | 作为 Go build tag，区分会改变生成代码的输入 |

`identity.hash` 包含源码文件列表，所以纯类型依赖变化（即使不改变生成的 NIR）也会更新记录。`artifactSha256` 刻意不含源码文件列表：同一份 NIR 回放时应当得到逐字节相同的产物，这一点在 01.07、02.09 和 05.06 已经验证。源码里的注释或类型依赖变化会重新检查、重新降低，并写一份新记录；如果 NIR 确实没变，复用同一份目标代码是正确结果，不是旧缓存误命中。

一次三文件构建的身份部分：


文件列表先按路径排序；文件部分只由 `路径 + NUL + sha256 + 换行` 连接后的字节参与计算，再与 NIR、配置和工具链一起生成完整身份。路径相对项目根（`--root`），所以同一个项目从不同工作目录构建得到同一身份。

`config` 和 `toolchain` 里的路径只是说明，不进入哈希；真正参与的是目标平台、`go`、修改版编译器、工具包装和固定支持目录的内容哈希。支持目录按整棵目录树计算，以后增加文件也会被覆盖。

## 一次构建的检查顺序

1. 载入依赖图，固定入口和每个依赖的字节快照，得到图哈希。
2. 读取工具链与编译器戳记，计算 `go`、编译器、工具包装、支持目录的内容哈希。
3. 用逐文件身份重组图哈希，与 `dump graph` 的 `hash` 比较。不一致报 `build.identity-mismatch`，不启动后端。
4. 在启动后端前重新读每个源码文件，与第 1 步固定的 sha256 比较。图建立后文件被换掉报 `build.file-changed`，不启动后端。
5. 组装完整身份，并用 `artifactSha256` 作为 `-tags` 的一部分。任何 NIR、配置或工具链变化都会换标签。
6. 构建成功后、发布之前，再次哈希 NIR 快照、`go`、修改版编译器、工具包装和支持目录。任何一项在构建期间被替换，报 `build.input-changed`，删除临时产物，不覆盖旧产物。
7. 产物和记录先写成临时文件，再经待定标记、旧文件备份和最终哈希复核发布；失败会恢复旧的一对，强杀留下的未完成发布由下一次构建恢复。

发布前的失败不改动旧产物和旧记录。发布期间失败会回滚；记录与产物对不上时，`VerifyPair` 拒绝把这次构建当成成功。详细顺序和临时文件见[构建事务、并发与清理](build-transactions.md)。

## 缓存边界

本项目没有业务级产物缓存：`build` 和 `run` 每次都重新载入图、重新检查、重新降低。没有一个需要关闭的「业务缓存命中」路径，也没有 `--no-cache` 参数。缓存只存在于底层 Go 构建，Go 的缓存键不含 NIR、被 `-toolexec` 替换的编译器和固定支持内容，所以构建标签补上这些身份。

标签使用完整的 64 个十六进制字符，不用短前缀。源码路径相同而内容变化时，NIR 变化会换标签；只改类型依赖时，NIR 可能不变，标签不变，但完整身份和构建记录会更新。判断正确性看记录里的身份和实际产物，不看缓存命中率。

## 边界

- 身份覆盖入口、显式相对导入的全部类型和值依赖、目标平台、固定支持目录和工具链；不覆盖编译器之外的任意环境变量或网络状态。
- 只支持 `darwin/arm64`，跨机器复用缓存不在验收范围。
- 不读取 `tsconfig.json`，也不把输出路径、时间或工作目录放进身份。
- `build-ir` 只编一份 NIR 时没有源码文件列表，身份仍覆盖 NIR、配置和工具链；它不能证明这份 NIR 来自哪份源码。
- 最终复核之后到后端真正读取之间仍存在极小的替换窗口；这项检查降低风险，不把构建描述成密封沙箱。
- 产物与记录不是跨两个文件的绝对原子事务；进程被强杀时可能留下 `.pending`，下一次构建会恢复，但在此之前不能把目标位置当作本次成功结果。

验收记录见[05.07 验收记录](../validation/05-07-identity.md)。
