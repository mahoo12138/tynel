## 命令契约

`cmd/tynel` 的帮助与解析现在共用同一组选项语义：

| 命令 | 接受的选项 | 输入路径基准 |
| --- | --- | --- |
| `version` | 无 | 不需要输入 |
| `check` | `--root`、`--json` | 入口相对 `--root` |
| `build` | `--root`、`-o`、`--target` | 入口相对 `--root`，输出相对当前工作目录 |
| `run` | `--root`、`--target` | 入口相对 `--root`，产物固定在 `.work/run/app` |
| `dump` | `--root` | 入口相对 `--root` |
| `build-ir` | `-o`、`--target` | 输入和输出相对当前工作目录 |

`--target` 省略时使用 `tools/toolchain/go.lock.json` 的主目标。首版只实现 `darwin/arm64`；其他值在启动前端或后端之前退出 3，不交叉编译，也不改用解释器。

产物和记录实际落在 `.work/validation/06-01/cwd/out/`，没有写进用户项目根；`examples/quote` 下没有生成 `out/`。构建记录保留用户写的相对输出路径 `out/quote`，记录里的入口是相对项目根的 `main.ts`。

路径修复前，同一命令会失败：

```text
tynel: 内部故障 (build.no-output): 构建报告成功但没有产出文件
```

原因是 `go build -C <项目根>` 会把相对临时输出解释到项目根。现在临时文件路径先转成绝对路径，再交给 `go build`；输出发布仍按调用时的工作目录解析。

## 负向验收

以下命令均从同一工作目录执行，退出状态由实际进程返回。

| 场景 | 命令 | 实际诊断 | 退出 |
| --- | --- | --- | --- |
| 未实现的目标 | `build … --target windows/amd64` | `target.unsupported`: 首版只支持 darwin/arm64；不交叉编译，也不会改用其他后端或解释器 | 3 |
| check 收到目标 | `check … --target darwin/arm64` | `cli.bad-flag`: check 不接受 --target；目标只影响 build、run 和 build-ir | 2 |
| 重复输出 | `build … -o out/a -o out/b` | `cli.duplicate-option`: build 的 -o 只能出现一次 | 2 |
| 未知选项 | `build … --bogus` | `cli.bad-flag`: build 不认识选项 "--bogus" | 2 |
| run 收到输出 | `run … -o out/a` | `cli.bad-flag`: run 不接受 -o；只有 build 和 build-ir 接受输出路径 | 2 |
| build-ir 收到项目根 | `build-ir quote.nir.json -o out/a --root .` | `cli.bad-flag`: build-ir 不接受 --root；只有 check、build、run 和 dump 接受用户项目根 | 2 |

不支持目标时 `out/unsupported`、`out/a`、`out/b` 都不存在；失败发生在启动后端之前，没有用旧产物或别的后端冒充成功。

`cmd/tynel` 的表驱动测试还覆盖了缺少入口、缺少 `-o`、多余位置参数、空 `--root`、重复 `--root`/`--target`/`--json`、未知命令和未知帮助主题；这些情况都要求退出 2。

## 帮助与实际参数

```zsh

$TYNEL help
$TYNEL help build
```

总体帮助区分「用户命令」和「开发与调试命令」，列出 `--root`、`-o`、`--json`、`--target` 的适用范围和路径基准。`TestHelpTopicsMatchCommandContract` 对八个帮助主题逐个检查：帮助必须存在，并且写出的关键选项与解析器接受的一致；`TestSourceOptionForms` 检查 `--root=<目录>`、`-o=<路径>`、`--target=<平台>` 三种等号写法。
