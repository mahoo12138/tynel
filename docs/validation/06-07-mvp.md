## 验收中发现并修复的问题

### 一元运算符错误分类

`-x` 是合法 TypeScript、当时能力检查放行，直到降低阶段才报 `lower.bad-unary`，类别是内部故障。这样的程序不是编译器内部坏了，而是一个明确未支持的操作。

修复后 `capability.Check` 在 `PrefixUnaryExpression` 看到非数字字面量时直接报 `cap.bad-unary`，CLI 退出 3；降低器保留同名防御，只处理绕过能力检查的伪造事实。新增 `compiler/capability` 单元测试和 `tests/source/testdata/errors/unary-variable.ts`。

### 用户函数占用入口名

用户函数名为 `main` 是合法 TypeScript，却会在降低阶段与固定宿主入口冲突。修复后能力检查报 `cap.entry-name`，退出 3，不再伪装成内部故障。新增单元测试和 `tests/source/testdata/errors/entry-name.ts`。

两项修复没有改变已支持程序的语义。最终矩阵是在修复后重新执行的，不复用修复前的测试结果。

## 已知限制

- 一元 `+` / `-` 只接受数字字面量；`-x` 按 `cap.bad-unary` 拒绝，后续需要新增取负操作才能扩大范围。
- 用户顶层函数不能使用固定入口名 `main`，按 `cap.entry-name` 拒绝。
- 输出拼写以 Tynel 为准：`+Inf` / `-Inf` 与 Node 的 `Infinity` / `-Infinity` 不同，差分测试只归一这两种拼写。
- 不支持字符串、对象、数组、接口记录、联合类型、泛型、闭包、类、异常、异步、`for`、`switch`、`try`、默认/命名空间导入、CommonJS、动态导入和任意 Go 绑定。
- 模块级 `let`、函数捕获模块级运行时值、顶层控制流明确拒绝；模块级 `const` 按初始化计划执行。
- 仅验证 `darwin/arm64`；没有 Windows、其他架构、其他 macOS 版本或跨机器逐字节相同的承诺。
- 没有命令行参数、标准输入、性能、深递归栈、栈溢出和通用 GC 的验收；这些不属于首版契约。
- 模糊测试只覆盖 NIR 解码器，测试时长 15 秒，不能替代穷举或形式化证明。
- 06.06 的独立运行在同一台物理 Mac 的 Seatbelt 进程中完成，不是另一台机器或虚拟机；它证明了无源码/NIR/Node/编译器目录访问依赖，不证明跨机器运行。
