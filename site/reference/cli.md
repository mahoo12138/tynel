# 命令行 API

本页是 `tynel` 的命令契约：参数类型、默认值、路径基准、成功输出与退出状态。日常用法见 [CLI 使用](/guide/cli)；失败的字段与恢复动作见[诊断与错误码](/reference/diagnostics)。

## 用户命令

### tynel version

```text
tynel version
```

显示程序版本、目标平台与配套工具身份。身份来自锁文件与准备报告，不内置第二份常量。不在项目目录内时仍输出程序版本，目标平台标为未知，退出 0。

### tynel check

```text
tynel check <file.ts> [--root <目录>] [--json]
```

类型检查、能力判断、降低并验证 NIR，不生成机器码，不检查后端工具链。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `file.ts` | 路径 | 必填 | 入口，相对 `--root` 解释 |
| `--root` | 目录 | 编译器检出根 | 项目根，只能出现一次 |
| `--json` | 标志 | 关闭 | 完整结果写标准输出 |

成功：标准输出一行摘要；`--json` 时输出诊断、能力结论、函数数量与 `verified`。不接受 `-o` 与 `--target`。

### tynel build

```text
tynel build <file.ts> -o <路径> [--root <目录>] [--target <平台>]
```

编译成原生程序，不运行。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `file.ts` | 路径 | 必填 | 入口，相对 `--root` 解释 |
| `-o` | 路径 | 必填 | 输出，相对当前工作目录；可写 `-o=<路径>` |
| `--root` | 目录 | 编译器检出根 | 项目根 |
| `--target` | 平台 | 锁文件主目标 | 只接受 `darwin/arm64` |

成功：输出产物路径、源码与 NIR 哈希、构建记录位置，并在同目录写 `<产物>.build.json`。失败不覆盖旧成功产物。

### tynel run

```text
tynel run <file.ts> [--root <目录>] [--target <平台>]
```

每次重新编译并执行本次产物，产物固定放在 `.work/run/app`，不接受 `-o`。构建失败直接返回，不执行遗留文件。程序启动后，其退出状态原样传出。

## 开发命令

| 命令 | 作用 |
| --- | --- |
| `tynel dump facts\|nir\|graph\|modules\|init <file.ts> [--root <目录>]` | 输出 JSON 视图；不接受 `-o`、`--json`、`--target` |
| `tynel build-ir <NIR> -o <路径> [--target <平台>]` | 从 NIR 回放；不接受 `--root`，输入输出相对当前工作目录 |
| `tynel toolchain` | 列出 SDK 与 `go`、`compile`、`link`、`asm` 的实际路径 |
| `tynel toolchain which <名>` | 只解析一个工具，输出绝对路径 |
| `tynel help [命令]` | 总体用法或单个命令说明 |

## 全局选项

| 选项 | 取值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--diagnostics` | `human` / `json` | `human` | 可写在命令前后，也可写 `--diagnostics=json` |

`--root`、`-o`、`--target`、`--json` 重复出现按用法错误退出 2。未知选项明确报错，不忽略、不传给其他工具。

## 路径规则

- 入口相对 `--root` 解释；省略 `--root` 时项目根是编译器检出根，而不是当前工作目录。
- `-o` 相对当前工作目录解释。
- 源文件的显式相对导入按来源文件目录解析；`--root` 只限定许可根。
- 路径大小写精确；符号链接解析后不得越出项目根。

## 构建记录

`<产物>.build.json` 的字段：

| 字段 | 内容 |
| --- | --- |
| `source` | 入口路径、sha256、字节数；从 NIR 构建时无此项 |
| `graphHash` | 入口与全部依赖的图哈希；从 NIR 构建时无此项 |
| `identity` | 完整输入身份：入口、全部类型/值依赖、NIR、配置、工具链与 `artifactSha256` |
| `input` | 实际编译的 NIR 快照路径、sha256、字节数 |
| `toolchain` | 锁定的 Go 版本与目标平台 |
| `tools` | `go`、修改版 `compiler` 及其 sha256、`toolexec`、build tag、快照路径 |
| `output` | 产物路径、sha256、字节数 |

源码 → NIR → 产物是一条哈希链。产物与记录先写临时文件，经 `.pending` 标记、备份与哈希复核后发布；进程内失败回滚，强杀留下的 `.pending` 由下一次同输出构建恢复。同一输出由 `flock` 保护，第二个构建不排队，按 `build.output-busy` 退出 4。

## 输出分流

| 输出 | 内容 |
| --- | --- |
| 标准输出 | 命令结果：check 摘要或 JSON、build 产物信息、dump JSON、被运行程序的输出 |
| 标准错误（human） | 诊断、宿主重建进度、被运行程序的标准错误 |
| 标准错误（json 诊断） | 单个 JSON 信封；进度被丢弃 |

## 退出状态

| 状态 | 类别 | 典型原因 |
| --- | --- | --- |
| 0 | 成功 | 命令完成 |
| 1 | 源码错误 | 语法、类型、未定义名称、坏 NIR |
| 2 | 用法错误 | 未知命令、缺参、多参、重复或未知选项 |
| 3 | 能力限制 | 写法合法但后端不支持，或请求未实现的目标 |
| 4 | 环境缺失 | 工具链未准备、编译器过期、输出不可写、同输出并发 |
| 5 | 内部故障 | 编译器自身、前端宿主或外部进程失败 |

`run` 例外：程序成功启动后，其退出状态原样传出。退出状态只由诊断类别决定，命令实现不各自约定数字。

## 运行依赖

| 谁 | 需要什么 |
| --- | --- |
| 编译器本身 | 已准备的 `.work/toolchain`；首次构建宿主需要前端源码与模块缓存；build/run 还需要修改版编译器 |
| 被编译的程序 | macOS 系统库 `libSystem` 与 `libresolv`；Go 运行时已在 exe 内，不依赖 Node、Go 工具链或本项目 |
