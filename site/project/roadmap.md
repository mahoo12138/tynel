# 路线图与边界

本页区分三种状态：已验证、明确计划、不在目标内。计划不表示可用；站点其他页面也不会把计划写成已经实现。

## 已验证（MVP，2026-11-09）

- `number` / `boolean` / `void` 子集：函数、递归、分支、短路、三元式、`while`、赋值、多文件模块。
- 命令契约：`version` / `check` / `build` / `run`，统一诊断与退出状态。
- 构建事务：失败不覆盖旧产物，同输出并发拒绝，中断可恢复。
- 发行目录与独立运行：搬移后构建成功，exe 在空目录、清空环境下运行。
- 目标平台：`darwin/arm64`，验收基线为 Apple M4 Mac mini。

逐项状态见[语言特性总览](/language/features)。

## 明确计划

| 方向 | 当前状态 |
| --- | --- |
| `windows/amd64` | 保留在延迟目标列表；没有可执行的准备命令，`--target` 拒绝 |
| `for` 循环 | 未排入已完成的 6 个节点 |
| 变量取负（`-x`） | 需要额外的取负操作，当前 `cap.bad-unary` 拒绝 |
| 模块级 `let` 与模块变量捕获 | 当前分别按 `cap.module-let`、`module.captured-variable` 拒绝 |
| 取余、位运算、定宽整数 | 未纳入首版 |
| 用户态并发 | Go 运行时调度器已随产物分发，构成基座；开放形式是后续决策，见 [Go 桥接与运行时](/internals/go-bridge) |

字符串、对象、数组等值类型的扩展属于后续语言工作，需要先确定原生表示，不在当前承诺内。

## 不在目标内

- 完整 TypeScript 兼容：泛型、类、闭包、异常、异步、npm 生态不是首版完成条件。
- Node 兼容：没有标准库、事件循环与完整 console 协议。
- 任意 Go 包绑定：用户程序不能导入 Go 库。
- 生产与跨平台承诺：首版只验证一个平台，产物依赖 macOS 系统库；不做签名安装包或远程发行。

## 变更怎样发生

语义和范围调整先更新规格契约、计划与测试要求，状态与验证分开记录。完成的阶段标签保持不动；后续文稿修订不重写已使用的实验历史。新能力必须带正向、负向与边界验收，才会从「计划」变成「支持」。
